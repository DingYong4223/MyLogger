# 打开schema实现方案

状态：交互稿与实现方案已通过，功能已实现，本地自动化与替身 adb 交互验证通过。

schema 早期交互已合并到[ADB 工作台统一可交互视觉稿](../design/index.html#schema)。本文件记录已实现的 schema 功能；工作台整体视觉稿已通过，不能视为全部功能已实现。

## 用户行为

1. 输入 `/`，现有命令列表新增 `/打开schema`，描述为“打开schema”，保留现有菜单项和顺序，`/help` 仍为末项。
2. 选中后回车查询可用设备：多个时先在现有设备弹窗选择，确认后在原输入栏提示“请输入schema（Enter 打开，Esc 取消）”；只有一个时自动选用并进入输入，无可用设备时提示并返回。
3. 输入非空 schema 后回车，执行等价于 `adb shell 'am start -W -a android.intent.action.VIEW -d "$schema"'` 的命令，其中 schema 替换为实际输入值。
4. 空输入保留输入状态并提示；Esc 取消并回到普通命令输入。输入 schema 期间不触发命令菜单或命令路由，即使内容包含 `/`、`/quit` 等文本也按参数处理。
5. 展示 adb 返回的结果或错误，随后恢复普通命令输入；执行失败不退出工具。

## 命令和错误处理

- 使用 `std::process::Command` 启动 adb，不经过本机 shell。
- adb 会把 shell 命令交给 Android shell，因此将 schema 作为一个经过单引号转义的参数，保留 `&`、空格、引号、`$()`、反引号等内容，防止被解释成额外命令；不做 URL 编解码或大小写转换。
- 拒绝空白输入及不能作为进程参数的 NUL 字符，不限定业务 URL scheme。
- 每次打开 schema 都重新查询设备，只列出状态为 `device` 的可用设备；多个时即使上次已选过也先让用户选择，使用所选 serial 执行 `adb -s`，不依赖默认设备。设备查询失败时回显错误，工具继续运行。
- 收集 stdout、stderr，处理启动失败、非零退出以及 `am start` 返回的启动失败信息，不将失败显示成成功。
- 不写入日志文件，不覆盖用户分析文件。
