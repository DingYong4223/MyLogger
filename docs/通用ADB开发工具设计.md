# 通用ADB开发工具设计

状态：产品设计建议，未实施。面向 Android 应用开发、联调、排障与测试；基于当前 Rust 工作区继续演进。

配套[统一可交互视觉稿](../design/index.html)已通过验收，视觉与交互由同一份 HTML 稿呈现；见[视觉稿说明](ADB工具视觉稿说明.md)。[首批实现方案](ADB工具箱首批实现方案.md)待批准。

## 1. 定位与推荐方向

将 MyLogger 扩展为终端里的 Android 开发工具箱：选好设备和应用后，从 `/` 菜单完成安装启动、页面跳转、日志采集、截图录屏、文件传输、网络联调和问题取证。

核心体验是“少记命令，明确目标，方便重复执行，结果可以带走”。保留现有 CLI/TUI，不以开发设备端 App、Web 控制台或云平台作为前提。

优先把日常开发闭环做完整，再补性能分析、系统设置和批量任务。无需一次性实现所有 ADB 命令。

以下依据当前源码核对，不把旧产品文档中的规划当成已实现功能。

## 3. 功能地图

P0：首批日常开发能力；P1：排障与效率增强；P2：专项能力，按实际需求追加。除上节明确列出的现有能力，下面均为规划。

### 3.1 设备与连接

| 功能 | 开发用途与交互 | 优先级 |
| --- | --- | --- |
| 设备列表与切换 | 展示型号、serial、系统版本、连接方式、状态；搜索选择 | P0 |
| 设备概览 | 查看 API、ABI、分辨率、密度、存储、电量等，支持复制摘要 | P0 |
| 连接诊断 | 区分 adb 不存在、未授权、离线、设备断开；提供对应处理入口 | P0 |
| 无线调试 | 输入配对地址与配对码，再连接调试地址；记录常用连接地址 | P1 |
| 多用户/工作资料 | 展示 user 列表，明确应用操作针对哪个 Android user | P1 |
| 重启与 ADB 服务管理 | 正常重启设备、手动重启本机 ADB server | P1 |

无线配对优先支持 Android 11+ 的系统无线调试；配对端口和连接端口可能不同，不混用。旧式 `tcpip` 单独作为高级操作，不自动开启。重启本机 ADB server 会影响其他工具，必须明确提示影响范围。

### 3.2 应用安装与生命周期

| 功能 | 开发用途与交互 | 优先级 |
| --- | --- | --- |
| 应用列表与选择 | 搜索已安装包名；查看系统/第三方标记、版本、UID、安装路径 | P0 |
| 安装 APK | 选择本地 APK，覆盖升级并保留数据，显示安装进度和错误原因 | P0 |
| 启动/停止/重启 | 启动入口 Activity、force-stop、重新启动 | P0 |
| 查看当前页面 | 展示前台应用、Activity 和任务栈，复制组件名 | P0 |
| 卸载与清数据 | 明确包名、设备和 user，分别提供卸载、清全部应用数据 | P1 |
| Split APK 安装 | 选择同一应用的 base 与 split APK，使用安装会话安装 | P1 |
| APK 导出 | 获取已安装 base/split 路径并导出文件清单 | P1 |
| 权限管理 | 查看权限状态，授予/撤销系统允许 shell 修改的运行时权限 | P1 |
| 调试进程 | 查看进程、PID、是否可调试；按需提供 JDWP 转发入口 | P2 |

安装失败应区分签名不一致、版本降级、ABI 不兼容和空间不足，不自动通过卸载重试。默认“覆盖升级”不附带降级或清数据。AAB 不是 APK，后续可调用用户已安装的 bundletool，不在首批内置转换链。

### 3.3 页面、schema 与 Intent 联调

| 功能 | 开发用途与交互 | 优先级 |
| --- | --- | --- |
| 打开 schema | 保留现有输入、设备选择、历史恢复能力 | P0，已有基础 |
| schema 收藏 | 为常用 URI 命名、按项目/应用分组，选择后先填入编辑框 | P0 |
| 参数编辑 | 保留原 URI，查看并编辑 query，避免反复改长字符串 | P1 |
| 指定目标应用 | 可选目标包名，避免多个应用都能处理时跳错应用 | P1 |
| 启动指定 Activity | 输入/选择组件，支持 action、data、category 和类型明确的 extras | P1 |
| 解析跳转目标 | 查询系统可解析的目标，辅助区分无匹配页面、权限和应用未安装 | P1 |
| Broadcast/Service | 显式发送调试广播或启动允许的 Service，显示系统拒绝原因 | P2 |

收藏 URI 原文与参数编辑分开：打开编辑器时不自动重排、解码再编码整个 URI，避免破坏嵌套 URL、重复参数及签名参数。普通 VIEW 不暗中附加清任务栈或强制停止选项。非导出组件和后台启动限制仍服从 Android 系统规则。

### 3.4 日志与问题定位

| 功能 | 开发用途与交互 | 优先级 |
| --- | --- | --- |
| 当前应用日志 | 按 UID/PID 等可用能力过滤，覆盖应用多进程；重启后更新进程信息 | P0 |
| 实时筛选 | Tag、级别、关键词、排除条件；暂停滚动和搜索 | P0 |
| Crash 快速定位 | 提取堆栈、进程、时间和相邻日志，保留原文来源 | P0 |
| 时间段导出 | 将复现前后日志与时间标记导出，减少整份日志搬运 | P1 |
| ANR/Native 线索 | 汇总可读取证据；受限路径显示不可读取，不伪装完整诊断 | P1 |
| 规则与收藏过滤器 | 保存项目常用 Tag、关键词和错误模式 | P1 |

先修复现有“按包名文本匹配”的准确性，再宣称应用日志过滤。后台进程重启、多进程、isolated process 的覆盖程度需要分别说明。保留已有命令语义；新采集入口默认不清历史日志，“清空并抓取”继续显式提供。

### 3.5 截图、录屏与界面检查

| 功能 | 开发用途与交互 | 优先级 |
| --- | --- | --- |
| 截图 | 保存 PNG，显示本地路径，可手动打开 | P0 |
| 录屏 | 开始/停止、显示录制时长，停止后拉取视频并检查完整性 | P0 |
| UI 结构导出 | 导出 UIAutomator XML，搜索文本、资源 ID 与 bounds | P1 |
| 常用按键与手势 | 返回、主页、最近任务，点击、滑动与坐标输入 | P1 |
| 打开镜像工具 | 检测并调用用户已安装的 scrcpy | P2 |

截图使用二进制输出路径，不通过文本解码保存。录屏时长、编码器和尺寸按设备能力校验；取消本地任务不代表设备端录制进程已停止，需要显式收尾。安全窗口可能黑屏，UI XML 也无法完整描述游戏、WebView 或自绘画面。`adb shell input text` 不承诺任意中文输入，中文需另行选择有授权的输入方案。

### 3.6 文件、应用数据与数据库

| 功能 | 开发用途与交互 | 优先级 |
| --- | --- | --- |
| Push/Pull | 输入或选择两端路径，显示进度，重名时明确覆盖策略 | P0 |
| 设备文件浏览 | 从 shell 可访问目录开始，浏览、下载和上传 | P1 |
| Debug 应用数据 | 对支持 `run-as` 的应用导出指定文件、SharedPreferences | P1 |
| 数据库导出 | 导出可访问数据库，明确一致性和 WAL 状态 | P1 |
| 本地打开文件 | 将导出文件交给已安装编辑器或数据库工具 | P1 |

普通设备不承诺访问其他应用私有目录，`run-as` 依赖目标应用允许调试且系统支持。运行中的 SQLite 文件单独 pull 可能不一致；优先采用应用提供的快照/导出能力，无该能力时由用户选择停止应用后采集可访问文件集，不能将其宣传为热备份。

### 3.7 网络与本地服务联调

| 功能 | 开发用途与交互 | 优先级 |
| --- | --- | --- |
| reverse/forward 管理 | 列表、新增、删除指定映射；常用“手机访问电脑服务”快捷入口 | P0 |
| 网络概览 | 查看设备 IP、路由和可读取的网络状态 | P1 |
| 代理设置 | 查看、设置、恢复工具修改前的系统代理 | P1 |
| 跳转网络设置 | 快速进入系统 Wi-Fi、应用设置等可解析页面 | P1 |
| 常用服务预设 | 保存开发服务端口与跳转地址，选择后预览执行 | P1 |

端口映射以选定 serial 为准，不默认 `remove-all`。系统代理未必被所有网络库采用，设置代理不等于能抓到全部 HTTPS；证书信任和证书绑定需要应用侧配合。弱网、断网、VPN 和网络切换依赖设备权限，后续按能力支持，不保证任意手机均可由 ADB 完成。

### 3.8 性能与系统状态

| 功能 | 开发用途与交互 | 优先级 |
| --- | --- | --- |
| 内存快照 | 读取当前应用 meminfo，比较多次 PSS 等指标 | P1 |
| CPU/进程观察 | 低频采样 CPU、线程、内存，保存时间序列 | P1 |
| 启动耗时 | 重复启动并统计 `am start -W` 输出，区分是否先 force-stop | P1 |
| 帧耗时线索 | 读取可用 gfxinfo/framestats，展示采样范围和适用条件 | P1 |
| Perfetto 采集 | 提供少量场景预设，拉取 trace 后由外部工具分析 | P2 |
| 系统环境切换 | 密度、分辨率、字体、动画倍率等支持项，修改前记录原值并提供恢复 | P2 |

`am start -W` 的耗时不等于应用首帧/完全可交互时间；force-stop 后启动也不能证明清除了文件缓存。gfxinfo 不代表任意渲染引擎的完整 FPS。第一阶段只提供有来源的指标，不生成缺乏基准的“性能评分”。

### 3.9 开发工作流与问题包

| 工作流 | 用户操作与产物 | 优先级 |
| --- | --- | --- |
| 安装并运行 | 选择 APK → 设备 → 安装 → 选择/确认应用 → 启动 | P0 |
| 抓日志并打开页面 | 选择设备/应用 → 开始采集 → 输入或选择 schema → 复现 → 停止采集 | P1 |
| 本地服务联调 | 选择设备 → 添加指定 reverse → 打开应用/schema → 退出时保留或删除该映射 | P1 |
| 收集问题包 | 记录设备/应用信息、选定时间日志、命令结果；截图/录屏由用户选择加入 | P1 |
| 完整 bugreport | 显式发起系统 bugreport，显示任务进度和导出路径 | P1 |
| 收藏动作组合 | 将已稳定的内置操作保存为少量参数化步骤 | P2 |

问题包建议包含 `manifest.json`、设备与应用摘要、日志片段、执行结果和用户选择的附件。每项证据记录 serial、包名、采集时间与成功/失败；部分步骤失败也保留已经取得的材料。导出前可选脱敏和排除附件，不自动上传。

| 功能 | 设计 | 优先级 |
| --- | --- | --- |
| 命令搜索 | `/` 后按中文名称、英文别名和描述搜索；分类结果，不堆成长菜单 | P0 |
| 应用上下文 | 显示当前设备、包名和 Android user；避免重复输入与误操作 | P0 |

| 高级 shell | 显式高级入口，展示实际命令；与普通参数输入分开 | P2 |

不默认将所有历史 URI 和 extras 写入磁盘。跨重启记忆先通过显式收藏实现；若后续增加持久历史，再单独设计保存范围、保留条数和清除入口。执行成功与否都可进入历史，但记录成功、失败、取消状态，取消的未提交输入不算已执行记录。

## 4. 统一交互

以下为信息结构草案，不是已验收的视觉稿。

```text
设备：Pixel / serial        应用：com.example.app        用户：0

最近操作 / 执行结果 / 当前任务

输入：> /                         ↑↓ 历史
  设备        查看设备、切换、无线连接
  应用        安装、启动、停止、应用详情
  页面        打开schema、收藏、Intent
  日志        抓取、过滤、Crash
  媒体        截图、录屏
  文件        浏览、Push、Pull
  网络        Reverse、Forward
  诊断        内存、启动、问题包
```

统一操作顺序：动作 → 核对设备 → 必要时选择应用/user → 输入参数 → 执行 → 显示结果及后续动作。

- 单设备自动选用；多设备继续沿用当前“先选设备再输入参数”，显示上次选择作为默认高亮，不跳过用户选择。
- 历史重执行显示当前目标设备，沿用现有语义，不悄悄回到某条历史最初使用的设备。
- 切换设备时清理过期应用/进程上下文，再检查新设备是否有同一应用，不能沿用旧 PID。
- 菜单、设备列表打开时 ↑/↓ 选择列表；普通输入时切换历史；长输入保持光标可见。
- Esc 返回上一步/取消未提交操作；长任务提供明确停止入口，不把关闭弹窗当成已经停止设备端任务。
- 任务运行中允许查看结果；首批每台设备最多一个日志采集或录屏实例，不支持无限并发。
- 截图、清数据、重启等动作不自动附加到其他操作；界面只呈现本次操作需要的参数。

## 5. 命令设计

下面是候选入口，尚未实现。TUI 显示中文名称，保留英文别名供脚本使用。正式新增命令前核对现有兼容性，现有 `/打开schema`、`capture` 和 `analyze` 保留。

| TUI 名称 | 候选命令 | 关键参数 |
| --- | --- | --- |

| 安装 | `/install` | APK 路径；split 列表后续加入 |

CLI 逐步提供相同语义，例如候选 `MyLogger --device SERIAL --package PACKAGE schema URI`。非交互执行遇到多设备且未指定目标时明确失败，不等待键盘输入。路径、URI、extras 用结构化参数传递，不把用户输入拼成本机 shell 命令。

## 6. 沿用 Rust 架构的实现边界

| 层 | 复用与调整 |
| --- | --- |
| `mylogger-cli` | 参数解析、一次性执行、退出码与 JSON 输出；不复制 TUI 的业务步骤 |
| `mylogger-tui` | 菜单、设备/应用选择、参数输入、历史、任务展示；逐步移出执行编排 |
| `mylogger-core` | 动作描述、上下文校验、工作流步骤、分析及报告；保留现有分析模块 |
| `mylogger-tools` | ADB 进程、设备能力查询、安装/Intent/文件等命令和结果解析；保留现有调用方式 |
| `mylogger-llm` | 保持可选边界，首批不依赖 AI 才能完成基本操作 |

先实现少量明确的模块和结构，不引入插件系统、通用脚本语言或动态工作流编辑器。

需要先补齐的共用能力：

1. **统一执行结果**：目标设备、操作类型、耗时、退出码、stdout/stderr 和输出文件。退出码为 0 也检查安装/启动类命令的语义错误。
2. **执行生命周期**：短命令超时；长任务区分启动、停止、收尾、完成；取消时检查设备端进程是否仍存活。
3. **输出策略**：二进制与文本分开；默认生成唯一文件名，不覆盖用户已有文件；设备临时文件只清理本任务创建的内容。
4. **上下文管理**：serial、包名、user、能力探测；每次执行前校验目标仍可用，设备断开后不自动切到别的设备。
5. **命令描述统一**：菜单、帮助、别名、参数需求来自同一份内置描述，减少当前菜单、路由与工作流描述之间的重复。

这些结构按首批功能实际需要落地；不为未来功能提前制造大规模通用框架。

## 7. 权限与操作边界

- 默认覆盖普通授权设备的 shell 能力。`run-as`、root、userdebug 各自作为有条件能力，不为使用基本功能要求 root。
- 普通查询、启动、截图、拉取文件不增加反复确认；清数据、卸载、重启、覆盖文件等操作显示目标及不可恢复影响，再由用户明确执行。
- 安装、权限、网络与系统设置依赖系统版本和厂商实现；探测不支持时给出具体原因，不偷偷更换为更具破坏性的命令。
- 修改代理、密度等可恢复设置时记录原值，提供恢复入口；中途失败也能查到改动。涉及多个步骤时不承诺全部动作都可回滚。
- 用户主动执行原始 shell 时明确它是 shell；URI、文件名和普通文本始终是参数。不得把历史/收藏中的字符串当作脚本自动运行。
- 诊断包与收藏可能包含业务数据，只在本地保存；远程分享或 AI 上传需要另行设计和授权。

## 8. 分阶段交付与验收

| 阶段 | 交付范围 | 验收重点 |
| --- | --- | --- |
| A：共用基础 | 设备/应用上下文、菜单分组搜索、命令结果、超时/取消、文件唯一命名 | 双设备不串目标，断连不切设备，失败后仍可操作，取消不留下受管后台任务 |
| B：日常工具箱 | 应用列表、安装启动、前台 Activity、schema 收藏、应用日志过滤、截图录屏、Push/Pull、端口映射 | 完成“安装→启动→联调→采集→导出”；现有 schema 历史和长输入不回归 |
| C：排障闭环 | Crash/ANR 线索、内存/启动测量、UI XML、问题包、无线配对 | 指标有采样边界，证据有来源，权限不足不会生成虚假成功报告 |
| D：专项增强 | Split APK、Debug 数据导出、Perfetto、系统环境恢复、收藏动作组合 | 可取消、可恢复项确实可恢复，限制与失败保留在结果中 |

最小可用的第一批建议只交付：**设备/应用选择、APK 安装与启动、当前页面、schema 收藏、准确的应用日志、截图、Push/Pull、Reverse，以及贯穿它们的结果展示。** 录屏紧随其后，复杂性能分析放后面。

自动化用替身 adb 验证参数、目标 serial、退出码及 stdout/stderr；覆盖非零退出、零退出但语义失败、取消和断连。真正的安装、跳转、录屏、无线连接和多用户行为，需要按授权在实际设备验收，替身不能替代设备证据。

## 9. 待确认项

| 待确认项 | 确认内容 | 推荐 |
| --- | --- | --- |
| 工具名称 | 是否改名为 MyADB 或 Android 开发工具箱 | 产品先按 ADB 工具箱定位；暂保留仓库、crate、可执行名，避免与功能无关的改名成本 |
| 首批功能 | 是否一次实现完整功能地图 | 按 A→B 交付日常工具箱，再用实际需求决定 C/D |
| 设备选择 | 多设备是否自动使用上次设备 | 保持每次先选，默认高亮上次设备；历史重执行明确显示当前目标 |
| 历史持久化 | 是否把所有命令和 URI 写入磁盘 | 保持会话历史；仅显式收藏跨重启保存 |
| 交互形态 | 继续 TUI，还是增加桌面/Web 前端 | 优先 TUI＋CLI；视觉稿和实施方案批准后再动新界面 |
| 数据访问 | 是否要求读取任意应用私有目录 | 普通 shell 为基础，Debug 数据按 `run-as` 能力支持；不以 root 为默认前提 |
| 输出位置 | 临时产物和主动导出文件如何区分 | 开发验证放项目 `tmp/`；产品支持指定输出目录，默认唯一命名，不覆盖 |

本轮只形成产品设计，不修改功能、不执行设备操作。下一阶段如进入实现，先针对首批交付范围制作交互稿，再细化实施方案。
