# ADB工具视觉稿说明

状态：统一可交互视觉稿已通过用户验收。只使用一个预览入口，不另做静态视觉稿。[首批实现方案](ADB工具箱首批实现方案.md)也已通过，Rust 终端实现与验证见 [首批实现与验证](ADB工具箱首批实现与验证.md)。

## 预览入口

[打开统一视觉稿](../design/index.html)

直接用浏览器打开 `design/index.html` 即可，无需安装依赖、启动服务或连接设备。总入口转到 `design/adb-workbench/` 中的工作台，保留查询参数和页面锚点；该目录的 `index.html`、`style.css`、`app.js` 共同组成这一份稿件。

此前的 `design/open-schema.html` 已转向统一稿的 schema 流程，不再作为独立设计基准。[产品设计](通用ADB开发工具设计.md)保持功能规划入口。

## 视觉方向

- 延续终端开发工具的阅读习惯，以深灰工作区、细分隔线、紧凑操作列表和等宽命令文本组织界面。
- 主要颜色：背景 `#14191f`、面板 `#1b222a`、分隔 `#313d49`、正文 `#dee5ec`、焦点青灰 `#85cdd3`、进行中琥珀 `#e3bf7c`。成功和失败同时提供文字状态，不只依赖颜色。
- 中文标题与表单使用系统无衬线字体；serial、URI、端口、输出使用本机等宽字体，无外部字体依赖。
- 按用户要求移除整个左侧功能导航，顶部固定设备/应用上下文，中部操作区与结果区使用全宽，底部保留命令输入和“搜索操作”入口。全部页面通过 `/` 搜索访问；内容区域在桌面保留主次双栏，窄窗口改为单栏。
- 面板圆角为 6px。设计是 Rust TUI 后续演进的工作台参考，不代表已新增一个 Web 产品或变更工程技术栈。

## 建议体验顺序

1. 工作台点“打开 schema”，在两台可用设备中选择一台，确认后再出现输入表单；待授权设备不可选择。
2. 填入详情示例并执行，查看输出中的设备和状态；在底部命令栏按 ↑ 恢复 URI，↓ 返回草稿，或到“执行历史”恢复输入。
3. 填入“无法解析示例”，查看失败结果和完整命令；失败后仍能编辑与执行。
4. 收藏一个 URI，在收藏页选择“填入并编辑”，重新核对设备后进入表单；不会自动执行收藏。
5. 在日志页按 E 级别和关键词筛选，查看 Crash 上下文。
6. 在截图录屏页开始录屏，再停止并保存；到任务页查看保存中的过渡和完成后的产物信息。
7. 在网络页创建端口映射，尝试重复端口，最后删除指定映射。
8. 设备页切换“无设备”后打开 schema，检查连接提示；切换“单设备”时直接进入 schema 输入。
9. 按 `/` 或点底部“搜索操作”，输入中文功能名或英文命令，通过 ↑/↓ 和 Enter 选择，Esc 关闭。

## 检查范围与边界

浏览器 DOM 验证覆盖 13 个模块、主要交互链路、背景节点在取消弹窗后仍保留、设备目标、长 URI 原生横向滚动、历史与草稿、结果和错误状态，以及桌面/窄窗口布局。检查视口为 1440×1000、1280×800、900×800、390×844，验证记录保存在项目 `tmp/`。

所有设备、日志、指标、执行结果和文件路径均为示例。点击不会执行 adb，也不会安装应用、修改设备、采集真实截图或访问真实文件；“导出结果”只下载演示 JSON。输入和新增收藏保留到本次页面刷新前。

视觉设计阶段未进行设备验证或截图验收；浏览器中的演示结果不作为实际功能验收。后续已批准首批实现继续采用 Rust ratatui：保留深灰底色、青灰焦点、顶部上下文、全宽操作/结果区和底部输入；终端与视觉稿均移除整个左侧导航，功能通过 `/` 搜索访问，Tab 只切换输入与结果。本批真实入口以实现方案和验证记录为准，完整视觉稿中的后续能力仍为设计参考。
