# ADB工具箱首批实现方案

状态：统一视觉与交互稿、首批实现方案及终端界面改动均已获用户批准；首批实现已落地，验收边界见 [ADB工具箱首批实现与验证](ADB工具箱首批实现与验证.md)。

视觉基准：[design/index.html](../design/index.html)。功能规划：[通用ADB开发工具设计](通用ADB开发工具设计.md)。

## 1. 本批目标

在现有 Rust CLI/TUI 上完成日常开发闭环：选择设备与应用 → 安装/启动 → schema 联调 → 日志与截图取证 → 文件传输与端口联调 → 查看结果。

保留 MyLogger 工程、crate 和可执行名。HTML 是已通过的工作台布局与交互基准，实际交付仍为 ratatui 终端界面；不新建 Web 后端或迁移技术栈。终端按字符单元适配颜色、分栏、表格与弹窗，不承诺浏览器字体和像素尺寸一比一映射。

## 4. 模块和数据边界

### 4.1 最少必要的数据

- 操作目标：设备 serial、可选包名；本批 Android user 默认 0，不提供多用户切换。
- 操作描述：稳定动作标识、中文名称、英文别名、分类、所需上下文。菜单与帮助复用描述，现有命令保持兼容。
- 执行结果：动作、目标快照、起止时间、状态、退出码、stdout/stderr 摘要及产物路径。失败结果也能查看。
- 任务：短命令和持续日志任务，关联操作目标与取消状态；不提前实现任意任务依赖图。
- 收藏：名称、原始 schema、可选目标包名；不保存设备配对码或任意原始 shell 脚本。

以上是拟新增结构，名称以实施时周边代码为准，不代表当前已有类型。业务结果放 core，ADB 子进程与设备返回解析放 tools；TUI 只管理页面、焦点、表单与展示。遵循现有 tools → core 依赖方向，不引入循环依赖。

### 4.2 代码落点

| 模块 | 修改方式 |
| --- | --- |
| `mylogger-core` | 复用 `Intent`、`route_intent` 与日志模型；按需要新增内置操作描述及执行结果模块，不重写分析器 |
| `mylogger-tools` | 保留 `adb.rs`/`capture.rs`；按实际代码量新增应用、文件/截图、端口操作模块；共用参数转义、超时与结果处理 |
| `mylogger-tui` | 从现有 `lib.rs` 按工作台渲染、表单/选择器、执行协调拆出所需模块；保留已验证的文本编辑和历史行为 |
| `mylogger-cli` | 新子命令使用与 TUI 相同的 tools 操作，不复制 ADB 命令和业务错误判断 |

不增加插件机制、通用工作流 DSL、数据库或新的异步 UI 框架。文件读写、后台线程和消息传递优先采用标准库；收藏编解码复用工作区已有 serde_json，必要时只在相关 crate 声明已有依赖。

## 5. 关键交互与行为约定

### 5.1 设备与应用

1. 进入需要设备的动作前刷新可用设备；多设备继续先选再输入参数，默认高亮当前选择。
2. 持续任务固定绑定创建时的 serial。界面切换设备不会改变运行中任务的目标。
3. 断连后失败或停止当前任务，不自动转到另一台设备。设备切换后使旧 PID 和应用详细信息失效。
4. 目标设备确定后再按需选择应用；同包名在新设备上存在时重新读取版本和进程信息。
5. 历史恢复沿用现有“使用当前设备”的语义，但在输入栏旁始终展示目标；新选 schema 动作仍先走设备选择。

### 5.2 输入与导航

- 复用已有输入滚动和 Unicode 显示列计算，不截断 URI 或文件路径。
- ↑/↓ 在列表、弹窗中优先用于选项；普通输入中切换历史，恢复类型与草稿。收藏填入后不自动执行。
- 增加焦点切换和明确快捷键提示，列表、表单、输出区支持键盘导航；窄终端改为单栏，不让输入光标越界。
- 未提交表单关闭时不触发动作；取消弹窗保留背景页面与滚动状态。
- Esc 关闭上层或停止未提交动作；持续采集通过明确的停止操作结束。退出时清理本工具管理的子进程。

### 5.3 执行与取消

- TUI 从阻塞式 `event::read` 改为可轮询事件与后台任务消息的循环。短 ADB 命令在后台执行，不阻塞输入。
- 以标准库线程/消息通道管理本批任务；stdout/stderr 持续消费，避免管道写满死锁；文本展示使用有界缓冲，文件持续写入。
- 首批每台设备最多一个日志任务；支持切换页面查看结果和停止采集。
- 短命令设置合理超时，安装/文件传输使用对应的较长超时；超时与用户取消区分显示。
- 安装/启动命令检查语义错误，不能仅靠退出码判断成功。取消安装不假定设备状态已回滚，必要时重新查询包状态。

## 6. 各能力的实现约束

| 能力 | 实现要求与失败边界 |
| --- | --- |
| 应用列表/当前页面 | 读取 package 与 activity 信息；Android 版本/厂商输出不同，保留原始结果入口；解析不到时显示未知而非错误猜测 |
| 安装 | 验证本地 APK 存在；默认覆盖升级保留数据，不自动降级或卸载；签名不兼容/空间不足时停止并显示错误 |
| schema | 原 URI 作为设备 shell 的一个安全参数，保持查询顺序/编码；指定包名是显式参数，不自动添加 force-stop 或清栈选项 |
| 收藏 | 默认保存至用户配置目录下的 MyLogger 收藏 JSON；使用同目录临时文件与原子替换；损坏文件保留并报错，不覆盖；会话历史仍不持久化 |
| 应用日志 | 优先探测可用 UID 过滤；不支持时查询目标进程集合并按解析后的 PID 过滤，刷新进程信息以应对重启；不再把包名文本匹配宣称为应用过滤；isolated process 等覆盖缺口明确显示 |
| 日志输出 | 已有清空/不清空入口语义保留；新应用日志入口默认不清空；实时 UI 有界，输出文件不因暂停显示而停止写入 |
| 截图 | 使用 exec-out 的原始字节保存 PNG，stderr 独立处理；检测失败与无效文件，不把文本错误保存为图片 |
| Push/Pull | 本地/远端路径各自作为参数；新文件默认唯一命名，用户指定已存在目标时显式选择覆盖；失败保留可识别的部分产物并显示状态 |
| 端口映射 | 所有操作带 serial；正确区分 reverse/forward 的来源端口；已有来源端口冲突时提示，不静默替换；只删除指定条目，不 remove-all |

应用启动使用系统解析出的入口组件；启动/停止/重启共享目标检查。截图不隐式采集到其他工作流中。

## 7. 实施顺序

| 步骤 | 交付与前置关系 |
| --- | --- |
| 1. 共用执行与状态 | 参数边界、结果结构、后台消息、取消/超时、目标快照；替身 ADB 先验证失败路径 |
| 2. 工作台与选择 | 按已通过稿落地 ratatui 布局、分类搜索、设备/应用选择、焦点与结果区；迁移现有 schema 与输入历史 |
| 3. 应用与页面 | 列表、安装、生命周期、当前 Activity、schema 包名目标与收藏；CLI 同步提供入口 |
| 4. 日志任务 | 修复按应用过滤，后台采集、显示筛选、暂停与停止；保留文件分析及已有抓取命令 |
| 5. 截图与传输 | 二进制截图、Push/Pull、进度与产物；共用输出文件策略 |
| 6. 端口联调与收尾 | reverse/forward、任务/历史详情、帮助与 README、回归测试、Debug/Release 构建 |

每一步完成其对应的真实功能和失败处理，不用视觉稿示例数据填充实际界面。不自动实施后续批次能力。

## 8. 验收场景

| 场景 | 通过标准 |
| --- | --- |
| 0/1/多设备与未授权 | 无设备可恢复；单设备直达；多设备确认前不执行；离线/未授权不可选 |
| 设备与任务隔离 | 双设备操作携带正确 serial；切换上下文、断连、取消均不串设备 |
| schema 回归 | 特殊字符和长 URI 原样提交；↑/↓、草稿、收藏、失败后重试都有效 |
| 安装启动 | 安装成功后可启动；签名/版本错误保留结果，不卸载、不清数据 |
| 应用过滤 | 覆盖日志文本不含包名、主/子进程、PID 变化和不相关同名文本；能力不足有明确提示 |
| 日志任务 | 采集中可以操作界面；暂停只影响显示；停止后文件完成刷新，子进程不残留 |
| 二进制和文件 | PNG 可解析；路径含空格/引号；覆盖、失败与断连不会伪装成功 |
| 端口映射 | 双方向端口正确；冲突不覆盖；删除只影响当前设备指定条目 |
| TUI | 标准/窄终端、中文显示列、长输入、焦点顺序、弹窗进退和页面滚动不回归 |
| CLI 兼容 | 旧 analyze/capture/StartService 可用；新非交互命令目标不明确时失败，不等待输入 |

自动检查：`cargo fmt --all -- --check`、`cargo test --workspace`、`git diff --check`；完成后构建 `cargo build --workspace` 和 `cargo build --workspace --release`。

进程和 TUI 测试使用替身 adb 与 PTY；新增解析逻辑使用必要的合成输出夹具。实际设备验收只在用户明确授权时执行，构建和替身测试分别记录，不能代替安装、跳转、截图和传输的设备证据。

## 9. 主要风险与确认内容

| 待确认项 | 确认内容 | 推荐 |
| --- | --- | --- |
| 首批范围 | 是否按本方案先完成日常工具箱 | 按上述范围交付，完整视觉稿其余能力后续分批实施 |
| 实际形态 | HTML 与 Rust TUI 的关系 | 以视觉稿为结构和交互基准，实际实现继续用终端 TUI |
| 收藏存储 | 是否跨重启保留收藏 | 只持久化用户显式收藏，历史继续仅在当前会话保留 |
| 设备验证 | 本批是否要求实际设备验收 | 默认先完成自动化与构建，明确授权后再执行目标设备操作 |

系统输出差异、进程动态变化和任务取消是主要实现风险；通过能力探测、目标快照、失败夹具及真实设备专项验收控制。功能开发须以本方案批准为起点。
